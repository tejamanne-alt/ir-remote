# Audit 2026-11-09: correctness, robustness, resiliency

Scope: the whole repository, reviewed in four independent parts.

| Part | Findings | Fixed | Documented, not fixed |
| --- | --- | --- | --- |
| `packages/ir_transports` | 13 | 12 | 1 |
| `firmware/esp32_bridge` | 9 | 9 | 0 (one part narrowed) |
| `packages/ir_core`, `code_db`, `db_build` | 7 | 7 | 3 minor notes |
| `apps/remote` | 16 | 15 | 1 (feature gap) |

Method:
- Each auditor reproduced every finding with a temporary test or concrete
  input before reporting it. Every fix has a regression test that fails
  without the fix, except where marked.
- Firmware glue (`src/`) cannot be built or run in the sandbox. It was
  syntax-checked against the real ESP-IDF 5.5 `esp_http_server.h`, and CI
  builds it with PlatformIO. Nothing here was verified on hardware: H1 to H3
  are still open (`HARDWARE_TEST_PLAN.md`).

## ir_transports

1. **Broadlink could send twice.** A send-data ack that decrypted to garbage
   triggered a re-authenticate and resend, although the IR may already have
   been on air. Now the send is at-most-once, and the session is re-keyed
   before the next press.
2. **A learn cancelled while connecting kept going.** A socket that
   connected after the timeout stayed open. Both now close.
3. **An unpaired bridge could win automatic selection.** `Degraded` counted
   as usable. `Degraded.canSend = false` now marks "answers but cannot send"
   (not paired, or pairing cleared on the hub).
4. **Concurrent `register` calls for one ID leaked a transport** and could
   keep the older one. Register, unregister and dispose are now serialized,
   and a replacement is in place before the old transport is disposed.
5. **`dispose` iterated a map that could change** under it
   (`ConcurrentModificationError`). It now works on a copy.
6. **Stale health results were recorded for replaced transports.** They are
   now dropped.
7. **ESP `dispose` left learn streams open.** It now ends them.
8. **Timed-out HTTP requests kept their connection.** They are now aborted.
9. **Inter-chunk quiet time used the wall clock**, so a clock change could
   stall or shorten a gap. It now uses a monotonic clock (ESP bridge and the
   Android built-in transport).
10. **`transmit` threw** for a negative repeat count, or after dispose. It
    now returns a result (ESP bridge, Simulated, Android).
11. **`.local` names passed the LAN-only check**, but the system resolver can
    answer them with any address. `isLanHost` now accepts address literals
    only.
12. **Bridge requests followed redirects**, so a LAN bridge could send the
    app to any host (found by the app auditor). Redirects are no longer
    followed, and any non-2xx reply is an error.
13. **Not fixed: the 64 KiB WebSocket frame cap applies after buffering.**
    dart:io has no frame-size limit, so a hostile LAN host could make the app
    buffer one large frame. Accepted for v1, because hubs are LAN-only and
    paired. Noted at `maxBridgeMessageBytes`.

## ESP32 bridge firmware

1. **Critical: the bridge crashed on every boot.** The HTTP server opened a
   socket before the TCP/IP stack existed. Arduino 3.x creates the stack on
   the first `WiFi.mode()`, and lwIP aborts without it. `net::begin()` now
   calls `Network.begin()` first.
2. **Critical: WebSocket tokens were never checked on newer cores.**
   From Arduino-ESP32 3.3.11, esp_http_server skips the handler at the
   handshake. Any LAN host could receive every capture. Authentication is
   now in band (ADR-026):
   - The client's first frame carries the token, and the bridge answers
     `ready`.
   - Broadcasts go only to authorized sessions.
   - Unauthenticated sessions are closed with 1008 after 5 s.
3. **`409 busy` was unreachable.** A send blocked the only server task, so a
   second phone's send waited in TCP and went out after that phone had given
   up. Sends are now async requests, and the server keeps serving.
4. **A reply could reach the wrong request after a loop stall.** Jobs now
   carry a sequence number, and a 1 Hz sweep answers a job the loop never
   took.
5. **A held key produced captures over 4 s that could not be sent back.**
   Captures are now cut to the last frame that fits the pattern limits.
6. **Cleared tokens came back after a restart if NVS failed.** The write is
   now retried every second, with its own LED pattern.
7. **A second OTA during the restart window overwrote the new image.** It is
   now refused with 409.
8. **One stalled peer could freeze the server.** Fixes:
   - body reads have an absolute deadline;
   - broadcast sends time out after 1 s;
   - closing revoked sessions is retried until it runs.
9. **Refusals could be lost to a TCP RST.** A refusal now drains up to
   64 KiB of body within 2 s, so the client sees it. A larger refused upload,
   such as an OTA image with a bad token, is still closed. No in-repo client
   sends one.

## ir_core, code_db, db_build

1. **High: decoders accepted the first part of a longer frame.** The learn
   flow then saved a shorter, wrong signal. Examples:
   - a Gree-style 35+32-bit AC frame was identified as `NEC1-f16`;
   - a Toshiba-style 72-bit frame was identified as `NECx2`;
   - any codec's own frame plus 8 extra bits was still identified.

   In the pinned Flipper data, 565 raw captures were affected. After the
   last mark, NEC, LG, Panasonic, Sharp/Denon, RC5 and RC6 now require the
   end of the capture or the protocol's minimum gap, each derived from its
   IRP and cited in the codec.
2. **`identify` ignored the repeat frames in a capture.** NEC2 came back as
   NEC1, and NECx1 as NECx2, so held keys repeated the wrong way. When
   several protocols read the first frame identically, the following frame
   now decides.
3. **Pronto threw `ArgumentError` or produced 0 µs bursts** for tiny carrier
   divisors, breaking the FormatException-only rule. Carriers outside
   10–500 kHz are now a `FormatException`.
4. **RC6 rejected valid frames within ±25%**, because the 2t and 3t windows
   overlap. Bi-phase decoding now tries both unit counts, with a bounded
   search.
5. **The Flipper parser built every line before applying limits** (5 MiB of
   fields cost about 220 MiB). It now streams lines and caps fields per
   signal (32) and per file (100,000).
6. **irdb NECx rows with subdevice −1 were skipped** on a wrong assumption
   about the default. They now import with S = 255−D (ADR-021).
7. **The documented M2 gate command did not exist.** CLAUDE.md now points at
   `tools/scripts/check_code_db.sh`.

Gates after the fixes: the M1 codec line coverage is 97.65%. M2 reproduces
the bundled DB byte for byte (`1b5fa616…`, unchanged), because db_build
never calls the decoders.

Minor notes, not fixed:
- Sony and JVC end-of-frame checks are looser than their IRP minimum gaps.
- `Pronto.format` can write a carrier outside 10–500 kHz that `Pronto.parse`
  then refuses, for example a Flipper raw signal at 5 kHz.
- The NECx1 decoder does not check the ~D:1 repeat bit against D.

## apps/remote

1. **High: dragging to scroll sent IR.** Buttons now take part in the
   gesture arena (ADR-027).
2. **High: hold-to-repeat ignored the codec's timing.** NEC's first ditto
   came about 356 ms late, and Sony repeated every 119 ms instead of 45 ms.
   Repeats now follow the `RepeatSpec` (ADR-028).
3. **A matching answer could apply to the wrong code set.** Yes and No are
   disabled while a send is in flight, and stale results are dropped.
4. **The RC5/RC6 toggle never changed during matching.** The first press on
   the saved remote also repeated the last toggle. The toggle now alternates
   from the first send.
5. **Keys appeared twice** on TV, set-top box and projector remotes, so
   screen readers announced them twice. Each key is now placed once.
6. **Re-adding a paired bridge erased its token.** A re-add now updates only
   the address. Known bridges are marked in the discovery list.
7. **Learning could hang on a spinner** when the hub stopped listening. It
   now fails with a message and offers Try again. Also, the learn flow keeps
   the raw capture unless re-encoding reproduces its first frame. This is a
   second guard, behind ir_core finding 1.
8. **A backup the app made could fail to restore** (Flipper key names over
   80 characters). Names are capped where they are created. The importer now
   accepts what older exports wrote, and macros follow any renamed keys.
9. **Duplicate IDs made a restore fail silently.** They are now a format
   error, and every restore error is reported. The database was never
   changed.
10. **Some names failed silently** (emoji, Devanagari). The limit counted
    visible characters, but the database counts UTF-16 units. The dialog now
    counts UTF-16 units and shows the limit.
11. **`setState` ran after the pair screen closed.** Guarded.
12. **Non-UTF-8 files escaped error handling**, and one path left an empty
    remote behind. Both fixed.
13. **The AC panel could lose "last sent"** if closed mid-send. The state is
    now saved before the screen check. Not reachable yet, because no AC
    encoder ships.
14. **Hub discovery could leak** if the screen closed while it was starting.
    The browse is now stopped, and the multicast lock released, on every
    path.
15. **Transport names and details bypassed the ARB file**, and the code DB
    copy could leave a partial file behind or delete the old copy before the
    new one verified. Both fixed.
16. **Not fixed: rooms can't be managed after saving.** A remote can't be
    moved to another room, and rooms can't be deleted (the repository
    methods exist, with no UI). Recorded as an M7 task.

## What this audit cannot show

- Nothing here was tested on hardware, so the human gates (H1 to H3) still
  decide.
- Two items are the most important to try on a board first:
  - the boot fix;
  - in-band WebSocket authentication on the exact Arduino-ESP32 core that
    `espressif32 @ 8.0.0` resolves to.
